# UI Design Rules

## General
- The site should feel intentionally designed, not AI-generated.
- Prefer restraint over decoration.
- Establish a consistent visual system before creating individual sections.
- Do not redesign unrelated components while completing a task.

## Components
- Prefer shadcn/ui components when appropriate.
- Search shadcn MCP before creating complex UI components from scratch.
- Customize components so they match our design system.
- Use Lucide for interface icons.
- Never use emojis as icons.

## Layout
- Use a consistent max-width container.
- Maintain deliberate vertical rhythm.
- Avoid excessive cards.
- Do not put every section inside a rounded rectangle.
- Use asymmetrical layouts where appropriate.
- Avoid centering every heading and paragraph.

## Typography
- Use no more than 2 font families.
- Establish a clear type scale.
- Use meaningful variation in size and weight rather than random styling.
- Keep paragraph widths readable.

## Visual Style
- Avoid unnecessary gradients.
- Avoid glowing backgrounds unless explicitly requested.
- Avoid excessive shadows.
- Avoid excessive border-radius.
- Avoid generic SaaS aesthetics.
- Use photography or illustrations intentionally rather than as filler.

## Interaction
- Hover states should be subtle.
- Animations should communicate hierarchy or state.
- Respect prefers-reduced-motion.
- Avoid animation purely for decoration.

## Responsive
- Design mobile layouts intentionally.
- Do not simply stack the desktop layout.
- Verify navigation, typography, forms and major CTAs at common breakpoints.

## References
When reference images/sites are provided:
1. Analyze them first.
2. Identify reusable visual rules.
3. Do not blindly copy them.
4. Maintain the project's own brand identity.
